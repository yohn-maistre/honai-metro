# Connected UI review — 1 November 2026

The owner selected shadcn-svelte as the common baseline, with Abstraksi/Aksara accents. Taste v2.1.5's app-screen workflow and isolated Chromium screenshots were used to review the implementation at 390, 768 and 1440px. See design-tooling.md for exact component/palette sources and licences.

The baseline's missing feed h1, metadata below 11px and decorative gradient are corrected. Current typography has readable metadata, compact page titles, one level of useful object description and consistent icon/form/navigation treatments. Sidebar active state, tab state, keyboard focus, mobile sheet dismissal, form/dialog controls and touch access to mobile search are exercised in browser contracts. Reduced-motion rules remove component animation. The generated registry selectors were qualified against the pinned Bits UI DOM rather than accepted without checking.

The final Taste run has no FAIL findings when the two explicit brand allowances are applied: palette-purple and palette-cream. These allowances preserve the owner's requested lilac and warm Abstraksi ink; they are not accidental unresolved defaults. One WARN remains for empty space on a genuinely empty first-run feed. It is retained deliberately: a fixed application viewport has no synthetic posts, metrics or people added to fill it. Populated thread, organization/work, review, settings and encrypted-message screens use isolated synthetic fixtures and were visually inspected.

Native contrast checks cover the five family presets, extremes and 400 custom color seeds in both themes. Accent text meets 4.7:1 against the limiting ordinary surface and primary button labels meet 4.5:1. Invalid custom input is rejected; appearance persists in the browser. These checks do not replace a full accessibility assessment, physical-device testing or review of every possible user-supplied asset.

The three browser contracts verify real local engine behavior through the built UI, with no browser errors or fixture writes to production. They cover forum/Wiki mutations, Group/Space/sponsorship/work/result/context flows, protected account picking, mobile navigation/search and two independent browser contexts exchanging real MLS messages. Private plaintext and the local key phrase do not enter captured API requests or server envelope rows. A security-code comparison, encrypted local persistence, wrong-phrase rejection and blocking are checked. See the engine's commons-implementation.md for the experimental messaging threat model and remaining gates.

All installation, generation, builds, tests and captures run in cloud development. No phone-side build or install is required. Screenshots and raw inspector output remain in the ignored .taste-skill workspace; no private catalogue or real conversation is bundled as demo content.
