# ETNOS alpha: interface and content pass — 2 November 2026

Goal: a readable, useful forum on a small phone, with native news and optional parallel feeds on desktop. Existing membership, private data boundaries and invite-only posting stay authoritative. Screenshots and real browser journeys are the acceptance evidence; fixture checks do not qualify production security.

## Custom feature inventory and acceptance

- [x] Shell: flat sidebar; one mobile menu trigger; aligned feed switch; back navigation restores the previous entry's scroll position.
- [x] Loading: one thin progress line tied to pending requests; content skeletons; reduced-motion support; no duplicated route spinner.
- [x] Feed and threads: compact actions; desktop reply composer directly after the post; mobile bottom composer; nested reply target and paging remain functional.
- [x] Media: shared composer/feed video previews; origin-only YouTube referrer; lazy visible embeds without sound autoplay; image grid/viewer/ALT remains intact. Photon behavior is a reference, not a substitute for Strata authorization.
- [x] Composer: inline numbered poll choices, removal/addition, compact duration; optional event/link/warning controls; draft and retry behavior retained.
- [x] News: more image-led tiles; native reader with WPW summary, attribution, sources and actual places; in-app sharing; related discussions matched by canonical links under current access checks.
- [x] Context rail: avoid repeating Explore's news tiles; show useful community/wiki context for the current route.
- [x] Individual profile: readable identity, deliberate avatar and actions, posts/replies/media views; private relationships remain private.
- [x] Community profile: stronger identity, visibility/admission clarity, discussion/media/wiki/about views, clear join/manage controls.
- [x] Discovery: existing content and communities first; no invented membership, news or activity.
- [x] Search: command dialog and full results remain keyboard accessible; existing content and people discoverable.
- [x] Multi-column feeds: optional Lajur, maximum three independently loaded feeds; single active column on mobile; no extra polling on normal routes.
- [x] Appearance: tasteful selected-state accents and stronger optional grain/dither; readable focus/contrast; no GPU shader required.
- [x] Context/group/work creation: compact sections, custom choices, clear busy/error states; no old page spinner.
- [x] Community/wiki creation, join, moderation, editing, reporting and confirmation dialogs: shared spacing and action hierarchy; custom dropdowns; current permissions enforced.
- [x] Messaging/activities: preserve encryption, opt-in discovery, unread behavior and origin recovery. No new interoperability claims.

## Deliberate boundaries

WPW remains the news engine. ETNOS consumes only its published, bounded public projection. We reuse WPW's existing story clusters rather than adding an alpha-stage embedding/model pipeline. Related discussion means a shared canonical story/source link, not a claim that a classifier understood the conversation. Third-party article text is not scraped or republished in full.

No PDS rollout, domain/identity migration, broadcasting toggle, paid plan change or private corpus workflow is part of this visual pass. Experimental PDS and data stewardship remain separate documented tracks.

## Implementation checkpoint (3 November, Asia/Bangkok)

Implemented: native WPW news reader and image tiles; a route-aware rail; shared cover/title-first video cards with player creation only after Play; numbered/removable poll choices; desktop inline/mobile docked replies; back navigation with entry scroll and tab restoration; a flat sidebar and one mobile menu; thin request-lifecycle loading line and page skeletons; stronger identity headers/media tabs; optional Lajur feeds (maximum three, active-only loading on mobile); optional stronger grain/dither; compact creation forms; full-screen media with caption and ALT controls. Native news and Lajur code are lazy loaded.

Video clarification: automatically displaying a preview means **cover and title**, never autoplay or video buffering when scrolling. Provider metadata/thumbnail requests are separate from the player; fixed same-origin preview ports send no forum cookies or page context. The data-saver setting can defer covers as well.

Photos already use client-side resizing/re-encoding, a 512 KiB upload ceiling, four-image limit and metadata stripping. The new viewer does not weaken the existing community-scoped media route. Profile changes do not publish follower lists, private group membership or inferred ethnicity, and do not add avatar/banner storage.

The remaining wiki/engagement directions are documented in the Strata repository's `docs/wiki-and-community-engagement-2026-11-03.md`. Group-specific proposal permissions, source-linked review comments, Git exports, block editors and civic consultation reports are **not** claimed as implemented.

Validation receipts and production version follow once the final browser suite and deployment checks settle. Browser data remains isolated to loopback fixtures; no fake people, discussions or poll results are seeded into ETNOS.

Research references for the visual direction remain the owner's Threads/Bluesky screenshots, the existing Taste v2 direction, and Photon's image/native-video/embed patterns. The implementation keeps Strata's media authorization, upload re-encoding and current-read checks instead of copying Lemmy-specific transport code. Natural Earth map data is public domain; attribution/terms are included with app notices.

All inventory entries above were reviewed against the current alpha behavior. Completion marks this pass, not full PyFedi parity or production security qualification. The eight browser journeys, 5 UI checks, 74 engine tests, actual workerd checks, type checks and lint cover the documented implemented scope.
